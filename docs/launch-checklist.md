# 제시간에 · 실제 사용 전 남은 과정

현재 웹사이트는 이미 호스팅되어 있습니다. 닉네임·일정·투표·가상 장부는 서버 DB에 저장되며, 결제는 모의 기능입니다.
GitHub 소스 공개와 웹사이트 접속 권한은 서로 다른 설정입니다. 현재 사이트는 소유자 중심의 비공개 범위를 유지합니다.

## 1. 예약금 없는 친구용 베타

- 사이트 공유 범위를 정하고 실제 친구 계정에 접근 권한 부여
- 서로 다른 2~3개 계정으로 코드 참여, 각자 닉네임, 확정, 체크인, 취소·마무리 점검
- 모바일·다른 브라우저에서 재로그인 후 데이터가 유지되는지 확인

예약금 0원으로 사용하면 PG 결제 연동 없이 일정을 정하는 베타를 운영할 수 있습니다.
닉네임은 표시 이름이며 로그인은 계속 ChatGPT 계정으로 합니다. 익명 참여를 원하면 별도 인증·세션 설계가 필요합니다.

## 2. 실제 돈을 받으려면

- 선택한 PG에 예약금 예치·취소와 지각 시 다른 참여자의 모임비로 쓰는 모델을 설명하고 지원 범위 확인
- 가맹점 절차 진행, 테스트 상점과 라이브 키를 분리해 서버에 설정
- 서버 승인과 금액·주문·참여자 검증, 웹훅 검증, 중복 요청 방지 구현
- 실제 환불·실패 재시도·대사 기록 구현
- 결제 수납과 타인에게 지급하는 정산 흐름을 구분해 설계하고 검증

현재 모의 버튼·영수증·가상 잔액은 실제 승인·보관·송금 기능이 아닙니다. 테스트 키를 라이브 키로 바꾸는 것만으로 완료되지 않습니다.

공식 참고: [토스페이먼츠 API 키](https://docs.tosspayments.com/reference/using-api/api-keys), [테스트 환경](https://docs.tosspayments.com/guides/v2/get-started/environment), [카카오페이 온라인 결제](https://developers.kakaopay.com/docs/payment/online/common).

## 3. 운영 기준과 장애 대응

- 개인정보 처리·보관·탈퇴 기준, 취소·환불·지각 분쟁·투표 미응답 처리 기준 정리
- 자기 신고 체크인을 그대로 쓸지, 위치 확인 등을 추가할지 결정
- DB 백업·복구, 오류 알림, 접근·정산 감사 기록, 요청 제한 준비
- 유료 운영 전 실제 승인·취소·환불과 장애 시 복구 시나리오 검증
